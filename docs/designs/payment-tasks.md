## 결론

다른 직원이 공유 드라이브에 올린 파일과 내 메일 중 **나가는 비용 문서**만 골라, 지급 건마다 Google Tasks "비용 지급 일정" 목록에 기한과 함께 등록한다.
Apps Script가 15분마다 규칙으로 처리하고, 규칙으로 못 정하는 문서는 비공개 폴더의 **대기 시트 1장**에 올린다. Claude Routine이 평일 낮 2시간마다 그 시트를 읽고 판단 결과 JSON 1개를 남기면, Apps Script가 그것을 읽어 할 일로 만든다. API 비용 0원, PC가 꺼져 있어도 동작한다.

## Problem Statement

- 직원들이 공유 드라이브에 견적서·대관/임대/용역 계약서를 올린다. 그 안의 지급액·지급 일정을 내가 일일이 열어 보고 챙겨야 한다.
- 원하는 것: "다른 직원들이 공유 드라이브에 업로드한 파일에서 내 업무와 관련되어 있는 것만 필터링해서 할 일에 업데이트" (사용자 원문). 메일도 같은 기준으로 본다.
- 내 업무 = 경영관리 중 **나가는 비용 일정**(견적서 최종 지급액, 계약서 분할 지급 일정).

## What Makes This Cool

- 구독만으로 동작한다. Claude API 키·추가 과금 없음.
- PC를 꺼도 돈다. 규칙은 Google 서버(Apps Script)에서, 판단은 Claude 클라우드(Routine)에서.
- 내가 아무것도 열지 않아도 "언제 얼마를 누구에게"가 할 일 목록에 기한 순으로 쌓인다.

## Constraints

| 항목 | 기준 |
|---|---|
| 비용 | Claude API 사용 안 함(구독만). Google 쪽도 무료 할당량 안에서 |
| 실행 환경 | Apps Script(규칙·수집·등록) + Claude Routine(판단). 내 PC 불필요 |
| 업로더 노출 | 업로더가 내가 파일을 확인했다는 걸 알 수 없어야 함. 관리자 감사 로그에 남는 건 괜찮음 |
| 할 일 위치 | 별도 목록 "비용 지급 일정", 기한 자동 추출 |
| 범위 | 할 일 등록만. 원장·계약 만료 알림·금액 대사 없음(D2) |
| 불확실한 문서 | Routine 판단 대기 → 평일 기준 24시간 지나면 "[직접 확인]" 할 일 |

## Premises (사용자 동의, D8)

1. 대상은 공유 드라이브에서 **마지막 수정자가 내가 아닌** 파일, 그리고 내 Gmail에서 **내가 보낸 메일을 뺀** 메일.
2. 나가는 비용 문서만. 지급 회차 하나당 할 일 하나.
3. 규칙이 확실하면 바로 등록. 애매하거나 **공급자가 우리 회사**인 문서는 Routine으로. Routine이 평일 기준 24시간 안에 판단하지 못하면 "[직접 확인]".
4. 변경 감지는 Drive **changes API**(수정 시각이 옛날인 업로드도 잡기 위해).
5. 실제 계정 테스트로 업로더의 활동 대시보드에 내가 보이지 않음을 확인해야 완료.

## Cross-Model Perspective

독립 검토(Opus 서브에이전트) 요지와 처리:

| 의견 | 처리 |
|---|---|
| 유료 API를 부르는 `Claude.js`가 남아 있으면 제약 위반. 지워야 한다 | 반영 |
| Routine은 원본이 아니라 비공개 폴더의 사본·시트만 읽어야 노출 위험이 줄어든다 | 반영 |
| 규칙이 정말 주 경로인지 모른다. dryRun에서 규칙/대기/직접 확인 비율을 보여 줘야 한다 | 반영(dryRun 적중률 보고) |
| 원장 시트를 먼저 만들어라 | 기각(D2: 할 일 등록만) |
| 규칙만 먼저 돌려 측정 후 Routine을 붙여라 | 기각(D3: 한 번에) |

## Approaches Considered

- **A. 대기 시트 1장 (선택, D10)**: 판단할 문서를 비공개 폴더의 시트 한 장에 행으로 쌓고, PDF·이미지만 사본을 둔다. Routine은 시트 1개 + 사본만 읽고 결과 JSON 1개를 쓴다.
- B. 문서마다 Google 문서 1개: Routine이 파일을 여러 개 열어야 하고 폴더가 지저분해져 제외.
- C. 사본만 두기: 텍스트 문서도 전부 사본이 생기고 메타데이터(올린 사람·링크)를 따로 전달할 곳이 없어 제외.
- 제외(세션 중 결정): Claude API 직접 호출(비용), 측정 먼저(D3), 원장 시트(D2).

## Recommended Approach (A)

### 흐름

```
[Apps Script, 15분마다]
 1. 수집    공유 드라이브 changes.list + Gmail 새 메일
            - 내가 마지막 수정자인 파일 제외(lastModifyingUser.me)
            - 내가 보낸 메일 제외
 2. 판별    이름 키워드 또는 본문(지급·합계·부가세 + 금액)으로 후보
 3. 분류    규칙 확정 → 바로 할 일
            애매함 / 공급자 = 우리 회사 → 대기 시트에 행 추가 (+PDF·이미지는 사본)
            읽을 수 없는 형식(hwp 등) + 이름 키워드 → "[직접 확인]"
 4. 결과 반영  폴더의 decisions*.json 읽기 → 할 일 생성 → 행 삭제, 사본·JSON 휴지통
 5. 만료    평일 기준 24시간 지난 행 → "[직접 확인]" 할 일, 행 삭제, 사본 휴지통

[Claude Routine, 평일 09~18시 2시간마다]
 대기 시트 + 사본 읽기 → 판단 → decisions-<시각>.json 1개 생성(같은 폴더)
```

### 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 드라이브 변경 감지 | `changes.getStartPageToken` 저장 후 `changes.list`(supportsAllDrives, includeItemsFromAllDrives). 첫 실행만 `files.list modifiedTime >= 최근 7일`로 채움 | changes API는 과거를 못 보고, 수정 시각 기준 조회는 옛 mtime 업로드를 놓침 |
| 내 파일 제외 | `file.lastModifyingUser.me === true`면 건너뜀 | 공유 드라이브 파일엔 `owners`가 없음 |
| 공급자 = 우리 회사 | `COMPANY_ALIASES`(회사명 별칭 목록) 중 하나가 "공급자"(“공급받는자” 제외) 라벨 뒤 50자 안에 있으면 규칙 결과와 상관없이 대기열 | D5. 받을 돈을 지급 할 일로 잘못 만드는 것 방지 |
| 대기열 위치 | 내 드라이브 비공개 폴더 "비용 지급 일정 연동" 안의 시트 "판단 대기" | Routine이 원본을 직접 열지 않게 |
| 시트 열 | id · 문서 키 · 버전 · 출처(드라이브/메일) · 제목 · 원본 링크 · 올린 사람 · 받은/수정 시각 · 대기 사유 · 본문 텍스트(최대 20,000자) · 사본 파일 ID · 등록 시각 · 만료 시각 | Routine이 시트 하나로 판단 가능하게 |
| 사본 | PDF·jpg·png만. 드라이브는 `Drive.Files.copy`(supportsAllDrives), 메일 첨부는 파일 생성 | 텍스트로 못 읽는 형식만 Routine이 직접 읽음 |
| 결과 형식 | `{"decisions":[{"id","is_payment_document","document_type","counterparty","summary","payments":[{"description","amount","currency","vat","due_date":"YYYY-MM-DD","due_basis"}]}]}` | Routine 커넥터는 기존 파일 수정 불가, 새 파일 생성만 가능 |
| 결과 반영 | 시트에 없는 id·버전이 다른 결정은 무시. JSON이 깨졌으면 그 파일만 휴지통 | 문서가 그 사이 수정됐으면 옛 판단을 쓰지 않음 |
| 문서 수정 시 | 같은 문서 키의 대기 행을 새 버전으로 교체. 완료 안 한 이전 할 일은 지우고 새로 | 기존 동작 유지 |
| 만료 | 등록 시각부터 **평일 시간만** 세어 24시간 | 금요일 저녁 문서가 월요일 Routine 전에 만료되지 않게 |
| dryRun | 할 일·시트·사본·속성 아무것도 쓰지 않음. 로그에 만들 할 일과 **규칙 확정 / 대기열 / 직접 확인 / 제외(사유별) 건수** 출력 | 규칙이 주 경로인지 실제 데이터로 확인 |
| 유료 API 코드 | `Claude.js`와 관련 설정 삭제 | 제약(구독만) |
| Routine 지시문 | 저장소에 `routine-prompt.md`로 보관, `create_trigger`로 등록(사용자 승인 후) | 재현 가능하게 |

## Open Questions

| 질문 | 필요한 것 |
|---|---|
| 회사명 별칭(`COMPANY_ALIASES`) 실제 값 | 사용자가 설치 때 입력(정식 상호, 약칭, 영문명) |

| Routine 커넥터가 내 폴더에 JSON 파일을 실제로 만들 수 있는지 | 첫 Routine 실행에서 확인 |
| Drive API 읽기·복사가 업로더 활동 대시보드에 보이는지 | 전제 5의 실제 계정 테스트로 확인 |
| Routine 정확한 실행 분 | 등록 때 확정(정각 대신 몇 분 앞당김) |

## Success Criteria

| 구분 | 기준 | 확인 방법 |
|---|---|---|
| 코드 | Node 모의 테스트 통과: ① 옛 mtime 파일을 changes로 잡음 ② 내가 수정한 파일 제외 ③ 공급자=우리 회사 → 대기열 ④ 대기 행 기록 ⑤ 결과 JSON 반영 시 할 일 생성·행 삭제·사본 휴지통 ⑥ 옛 버전 결정 무시 ⑦ 금요일 저녁 등록 행이 월요일 오전엔 만료 안 됨 ⑧ 문서 수정 시 대기 행 교체 ⑨ dryRun이 아무것도 쓰지 않고 건수 보고 출력 | `node --test test/run.test.js` |
| 실제 계정 | dryRun 로그의 할 일·건수가 납득 가능 | 사용자 실행 |
| 노출 | 두 번째 계정으로 올린 테스트 견적서의 활동 대시보드에 내 이름이 안 보임 | 사용자 실행 |
| 연결 | 애매한 문서 1건이 Routine 한 주기 안에 할 일로 등록됨 | 사용자 확인 |

## Distribution Plan

- Apps Script: `payment-tasks/src/`를 script.google.com 프로젝트에 붙여 넣거나 `clasp push`. `dryRun` → `setup`(목록·폴더·시트·15분 트리거 생성).
- Routine: `routine-prompt.md` 내용으로 Google Drive 커넥터만 붙여 `create_trigger` 등록(사용자 승인 후).
- 빌드·배포 파이프라인 없음(개인용).

## Next Steps

1. `Claude.js`·관련 설정 삭제, 테스트 하네스 정리.
2. 드라이브 수집을 changes API로 교체(+첫 실행 7일 채움, 내 파일 제외).
3. `COMPANY_ALIASES` 공급자 규칙.
4. 대기 시트·사본·결과 JSON 반영·평일 24시간 만료(기존 임시 작업물의 `parseDecisions_`·`ingestDecisions_` 재사용).
5. dryRun 적중률 보고.
6. 테스트 ①~⑨ 작성·통과.
7. `routine-prompt.md`, README 갱신. 커밋·푸시, 초안 PR 갱신.
8. (사용자) dryRun 실행, 두 번째 계정 노출 테스트. (승인 후) Routine 등록.

## What I noticed about how you think

- 처음 설명이 넓게 잡히자 "아니 난 다른 직원들이 공유 드라이브에 업로드한 파일에서 내 업무와 관련되어 있는 것만 필터링해서 할 일에 업데이트 되면 되는데"라고 범위를 한 문장으로 좁혔다.
- "필요한 스킬 전부 다 설치하고 계획부터 다시 물어봐!!!!" — 코드보다 계획이 먼저라는 순서를 직접 요구했다.
- 두 번째 의견이 "측정 먼저"를 권했지만 "규칙 + Routine 한 번에"를 골랐다. 단계보다 한 번에 쓸 수 있는 결과물을 택했다.
- "공급자가 우리 회사면 Routine"을 골랐다. 받을 돈이 지급 할 일로 섞이는 오류를 규칙에 맡기지 않았다.
