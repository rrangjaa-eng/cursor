# 코딩 원칙

## 단순함이 먼저다
- 문제를 푸는 최소한의 코드. 추측성 코드·요청받지 않은 유연성·설정 가능성은 넣지 않는다.
- 한 번만 쓰이는 코드에 추상화를 넣지 않는다. 일어날 수 없는 상황의 에러 처리는 넣지 않는다.
- 200줄을 50줄로 줄일 수 있으면 다시 쓴다.

## 외과적으로 변경한다
- 꼭 필요한 곳만 건드린다. 주변 코드·주석·포맷을 "개선"하지 않는다. 기존 스타일을 따른다.
- 관련 없는 죽은 코드는 언급만 하고 지우지 않는다. 내 변경으로 쓰이지 않게 된 것만 치운다.

## 목표 지향으로 실행한다
- 작업을 검증 가능한 목표로 바꾼다: 버그 수정 → 재현 테스트 작성 후 통과, 리팩터 → 전후 테스트 통과.
- 여러 단계면 단계마다 확인 항목을 붙인 짧은 계획을 먼저 쓴다.
- 버그는 재현 → 원인 → 수정 → 회귀 테스트. 추측 수정 금지.

## 기본 규칙 (저장소에 규칙이 있으면 그쪽을 따른다)
- 새 의존성은 이유 한 줄과 함께 승인받고 추가한다.
- TypeScript에서 `any` 금지.
- 한 커밋 한 의도. 제목은 영어 접두어(feat:/fix:/docs:/chore:) + 짧은 요약, 본문은 한국어.
