# 디자인 지침 (화면·페이지·문서·슬라이드)

## 0. 우선순위
- 프로젝트에 디자인 시스템(토큰·SYSTEM.md·스타일 가이드·브랜드 가이드)이 있으면 그것을 따른다. 이 지침의 기본값(§3)과 섞지 않는다.
- 시스템을 벗어나야 하면 이유를 기록하고 시스템을 고친다. 화면 하나만 예외로 두지 않는다.
- 사용자가 이미 정한 디자인 결정은 바꾸지 않는다. 바꿔야 하면 묻는다.
- 디자인 개선 요청은 CSS·인라인 스타일 조정만으로 끝내지 않는다. 정보 구조·시각 계층·실제 컴포넌트·상호작용·목적에 맞는 요소(차트·표·모달·필터 등)를 함께 검토해, 데이터 정확성·접근성·반응형을 지키며 실질적으로 개선한다.

## 1. 만들기 전에 세 줄
1. 누가, 무엇을 하러 이 화면·문서를 보는가
2. 보는 사람이 할 주 행동 하나(또는 가져갈 결론 하나)
3. 성공 기준 — 무엇을 보면 잘 됐다고 판단하는가

## 2. 공통 원칙
### 읽지 않아도 알게
- 설명문·도움말 대신 이름·아이콘·배치로 뜻이 통하게 한다. 같은 말을 두 번 하지 않는다.
- 글은 오류·되돌릴 수 없는 일·잠김 같은 상태에만 한 줄로, 무엇을 하면 되는지를 쓴다. 사과·느낌표·과장 없이.
- 빈 화면에는 설명 대신 첫 행동 버튼.

### 고민하지 않아도 되게
- 알 수 있는 값은 기본값으로 채운다(오늘 날짜, 내 소속, 이전 입력값). 계산할 수 있는 것은 묻지 않는다.
- 할 수 없는 선택지는 숨기거나 비활성화하고, 비활성화하면 이유를 옆에 쓴다.
- 확인 창 대신 되돌리기. 확인은 되돌릴 수 없는 일에만.

### 다음 행동으로 이끌게
- 한 화면(한 섹션·한 슬라이드)에 주인공 하나, 주 버튼 하나. 나머지는 한 단계 낮춘다.
- 순서가 있는 일은 단계로. 필요한 값이 채워져야 다음 버튼이 켜진다.
- 위험한 동작은 주 동작에서 떨어뜨려 둔다.

### 같은 것은 같게
- 같은 역할은 같은 모양·같은 위치·같은 단어. 버튼 이름은 동사+대상(「견적 저장」), 결과 알림은 같은 단어+결과(「견적 저장됨」).
- 새 컴포넌트는 두 곳 이상에서 쓰일 때만. 먼저 있는 것을 찾는다.

### 모두가 쓸 수 있게
- 글자 대비 4.5:1 이상(큰 글자 3:1). 상태를 색만으로 전달하지 않는다(글자·배지를 함께).
- 키보드만으로 모든 동작이 가능하고, 포커스 표시가 보인다.
- 터치 영역 44px 이상. 폭 320px에서 가로 넘침 없음.

### 한국어·숫자
- 한글은 `word-break: keep-all`, 본문 행간 1.5~1.7.
- 금액은 쉼표, 우측 정렬, `tabular-nums`, 줄바꿈 금지. 번호·연도·전화번호에는 쉼표 없음.
- 날짜 `2026-09-18`, 시각 24시간제. 한 제품 안에서 표기를 섞지 않는다.

## 3. 기본값 (프로젝트에 시스템이 없을 때만)
- 값은 CSS 변수(토큰) 한 곳에 모으고, 화면 코드에 색·px를 직접 쓰지 않는다.
- 간격: 4px 단위 — 4·8·12·16·24·32·48·64.
- 글꼴: Pretendard(없으면 system-ui). 한 제품에 글꼴 하나, 굵기 400·600·700만.
- 글자 크기: 12·14·16·20·24·32·48. 한 화면에 4단계 이상 섞지 않는다.
- 색: 브랜드색 1개 + 중립 회색 9단계 + 상태색 3개(성공·경고·위험). 강조색은 주 행동·현재 위치·포커스에만.
- 모서리: 한 값(권장 6~8px). 그림자: 없음 또는 떠 있는 요소(메뉴·모달)에만 한 단계.
- 움직임: 반응 피드백만 120~200ms. 등장 애니메이션·숫자 카운트업·hover 확대 없음.
- 아이콘: 한 세트(Lucide 등)만, 16/20px.

## 4. 종류별
### 업무용 도구 (ERP·관리 화면·대시보드)
- 빠름이 먼저. 조밀하게(표 행 36~44px), 한 화면에서 끝나게.
- 표는 엑셀처럼: 칸 바로 입력, Tab·방향키 이동, 붙여넣기 여러 줄, 단축키 저장. 오류 칸은 표시하고 입력값은 보존한다.
- 입력 칸이 형식을 잡아 준다(쉼표 자동, 날짜 선택, 검색해서 고르기).
- 오류는 「원인 · 다음 행동」 한 줄. 예: `날짜 형식 오류 · 2026-09-18처럼`.
- 상태는 2~4글자 배지(대기·승인·반려). 대시보드 큰 숫자는 핵심 지표에만.

### 마케팅·소개 페이지
- 첫 화면에 무엇·누구를 위한·왜 지금 + 행동 하나. 스크롤하지 않아도 알 수 있게.
- 섹션 하나에 메시지 하나. 제목이 곧 메시지(「빠른」 대신 「견적 입력 30초」).
- 실제 사진·실제 수치·실제 사례 우선. 여백을 넉넉히, 글은 짧게.
- 이미지는 크기 최적화·지연 로딩. 폰에서 먼저 확인한다.

### 문서·보고서·슬라이드
- 결론 먼저. 슬라이드 제목은 주제가 아니라 결론 문장.
- 슬라이드 하나에 메시지 하나, 글머리 3~5개 이하. 문단보다 표·도식.
- 글꼴 2개 이하, 강조색 하나. 표·차트는 강조할 값 하나만 색을 준다.
- 차트는 축·단위·출처를 적는다. 3D·파이 여러 개·장식 격자 없음.
- 최종 형태(PDF·인쇄·발표 화면)로 뽑아서 확인한다.

## 5. 금지
- 흔한 AI 템플릿 느낌: 보라·네온 그라데이션, 유리(블러) 카드 남발, 이모지 아이콘, 가짜 통계·가짜 후기·가짜 로고
- 의미 없는 장식 번호(01/02/03), 버튼 끝 `→`, 「확인」「제출」「더 알아보기」 같은 빈 버튼 이름
- 스피너 남발(가능하면 자리 표시 뼈대), 과한 등장 애니메이션
- 표의 가로 스크롤을 폰의 기본 해법으로 쓰기
- 목업 이미지만 보고 판단하기 — 실제 화면·실제 출력물로 비교한다
- 외부 CDN에서 글꼴·스크립트를 즉석으로 끌어오기(프로젝트가 허용한 경우 제외)

## 6. 끝난 뒤 점검 (실제 렌더링 결과로 — 코드만 보고 판단하지 않는다)
1. 설명 글 없이 무엇을 하는 화면인지, 다음에 뭘 할지 보이는가
2. 주 행동(결론)이 하나로 눈에 띄는가
3. 사용자가 하지 않아도 될 결정·입력이 남았는가
4. 폭 320px(폰)과 1280px(PC)에서 넘침·겹침·잘림이 없는가
5. 대비·포커스·키보드 조작·터치 영역이 기준을 지키는가
6. 시스템(또는 §3 기본값)에 없는 색·크기·모서리를 새로 만들지 않았는가

## 7. 서브에이전트에 맡길 때
- 화면·문서 작업을 서브에이전트에 맡기면 이 지침(또는 프로젝트 디자인 시스템)의 경로를 지시문에 넣어 먼저 읽게 한다.
